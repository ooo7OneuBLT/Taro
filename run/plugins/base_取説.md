# plugins 取扱説明書（測る道具の作り方・使い方）

本体: `run/plugins/base.py`（規約そのもの）／道具は `run/plugins/common/`（28本）
最終同期: 2026-09-16

## このファイルは何をするか

**測る道具（プラグイン）をどう書くか**の決まり。規約そのもの（フックの一覧・
`intervenes` の名乗り）は `run/plugins/base.py` の説明文にある。ここは
**「何を出して、何を出さないか」**を決める。

---

## いちばん大事な決まり：道具は列を出す。数えるのはあと

> **出せる値は plugin で出力して、その出力をもとに測定する**
> （ユーザー指示・2026-09-16）

| | やること | やらないこと |
|---|---|---|
| **プラグイン** | 観測できた値を**列**としてCSVに出す | 数えない・率を出さない・判断しない |
| **測定**（`F/scripts/` など） | 出てきた列を**あとから**読んで数える | 走行中に動かない |

### なぜこうするか（実際に起きたこと）

`word_production` は「発話回数」を `len(self.rows)` ＝ **自分がためた行の本数**で
報告していた。ところが行は**太郎が黙った歩にも積まれていた**（`last_produce` が毎歩来る）。
さらに `exact_match = (generated_word == target_word)` が空文字どうしの比較で
**1（正解）**になっていた。分母と分子の両方が水増しされていた。

```
F2-130b   報告 95.8%  →  実際 86.1%
F2-130a   報告 89.4%  →  実際 71.4%
般化の差   6.4ポイント →  14.7ポイント
```

**直せたのは、列がCSVに残っていたから。**走行をやり直さずに数え直せた。
もし率だけを報告して列を捨てていたら、9〜15分の走行を全部やり直すことになっていた。

### 同じ作りの道具が4本あった（2026-09-16 実測）

```
word_production   "発話回数"      = len(self.rows)
word_learning     "発話イベント数" = len(self.rows)
babble_probe      "喃語_発話数"   = len(self.event_rows)
produce_snapshot  "発話スナップ"   = len(self.vecs)
```

「何を1行にするか」はそれぞれの `on_step` の中の暗黙の判断で、どこにも書かれていない。
だから**1本直しても残りは同じ形のまま残る**。これが「数え方を何度も直しているのに
繰り返す」の正体だった。

### 書き方

数えたい事実は**0/1の列**にして、合計を取る。

```python
# on_step
self.rows.append({..., "発話した": int(ctx.発話した)})

# report — 行の本数ではなく列の合計
声 = sum(r.get("発話した", 0) for r in self.rows)
return {"発話回数": 声, "記録した歩数": len(self.rows)}   # 分母の取り違えを防ぐため両方出す
```

## 導いた事実は自分で計算しない。`ctx` から読む

`run/context.py` の `Ctx` が、1歩に1度だけ計算して持ち回る。

| 読むもの | 中身 |
|---|---|
| `ctx.step` / `ctx.sim_sec` / `ctx.dt` | 時刻 |
| `ctx.model` / `ctx.data` | MuJoCo の生の状態 |
| `ctx.親の的` / `ctx.親の状態` | 親がいま差し出している物と、そのときの状態 |
| `ctx.スロット` | この場面にあるスロットと物の名前。**2択か8択かは場面で決まる** |
| `ctx.視線角` | スロットごとの視線のずれ[度]。**遮蔽は見ていない** |
| `ctx.視線の先` | いま見ている物。**遮られているものは選ばない**（光線で判定） |
| `ctx.発話した` | この歩で太郎が実際に声を出したか |

### なぜ自分で計算してはいけないか

`gaze_probe.py` と `word_production.py` が**同じ視線角の計算を別々に持っていた**。
どちらも `test_object1` / `test_object2` を決め打ちしていたが、目標Fの場面は8択なので
**存在しない2つを見ていた**。2026-09-15 に `word_production` だけ直し、`gaze_probe` は
残った。事実の作り手を1箇所にすれば、片方だけ直る状態そのものが無くなる。

### 視線は角度ではなく光線で

`run/world/visibility.py` は自分の説明文にこう書いている。

> ①角度だけ `gaze_angle()` … **遮蔽を見ないので単独では使わないこと**

にもかかわらず、2026-09-16 時点で測る道具28本のうち `visibility.py` を使っていたものは
**0本**だった。全部が `env._gaze_angle_to()`（＝①）を直接呼んでいた。
柵の向こうの物を「視界内100%」と報告した事故（2026-07-26・落とし穴 項51）と同じ道。

`ctx.視線の先` は②`visible_by_ray`（遮蔽を見る）で出している。
③`visible_in_image` は**使えない**：対象を指定する引数が無く、赤い画素の総数を数える
だけ＝目標Eの「赤い球1個」専用で、8択では物を区別できない。

## 列は場面の大きさに合わせる。決め打ちしない

スロットの数は場面で決まる（2択のことも8択のこともある）。CSVの見出しも
`ctx.スロット` から作る。

```python
スロット = sorted({k for r in self.rows for k in r["視線角"]})
w.writerow(["sim_sec", "親の的", ...] + ["視線角_%s" % s for s in スロット])
```

---

## 重い処理は N歩に1回

`on_step` は毎歩呼ばれる。OSやGPUへの問い合わせ・画像の描画・モデルの推論は
**間隔を空ける**。目安は `run_profile`（既定20歩に1回）。

自分がどれだけ時間を使ったかは**自分で測って列に出す**。`run_profile` は
`計測の秒` を出しており、実測で走行時間の **0.57%** だった。

## 道具は「読むだけ」。変えるなら名乗る

規約の本体は `run/plugins/base.py`。要点だけ：

```python
class MyPlugin(Plugin):
    name = "my_plugin"
    intervenes = None            # 読むだけ（既定）
```

太郎か環境か走行を**わざと**変える道具は `intervenes` に理由と
`doc/人間模倣からの逸脱リスト.md` の項番号を書く。名乗らずに変えているものだけが違反で、
`run/tools/check_plugins.py` が止める。

実例：`object_files.py` は眼球へ命令を出していたのに4か月気づかなかった。

## 作ったら登録する

`run/main.py` の `PLUGINS` に1行足す。足さないと
「知らないプラグイン」で走行が止まる（使えるものの一覧が出る）。

```python
from run.plugins.common.run_profile import RunProfile
PLUGINS["run_profile"] = RunProfile   # 何をする道具かを1行
```

## 実験ファイルからの使い方

```json
  "plugins": {
    "word_production": { "events_out": "F/logs/<実験>/太郎の発話.csv" },
    "run_profile":     { "out": "F/logs/<実験>/走行の負荷.csv", "every": 20 }
  }
```

- `true` だけ書くと設定は `{}`。`false` / `null` を書くとその道具は組み立てられない
- `run.csv` のある学習には `dashboard` が自動で足される（切るには `"dashboard": false`）

## 出るはずのものを宣言する

実験ファイルの最上位に `expect` を書くと、`run/tools/smoke.py` が**200歩の試し走行**で
答え合わせをする。本番（9〜15分）を捨てる前に捕まえられる。

```json
  "expect": { "発話イベント.csv": ["text", "target"],
              "走行の負荷.csv": ["1歩の秒", "メモリMB"] }
```

実例：F2-129 は4000歩・9分を完走してから「`goal_id` が全行で空」と分かった。
`expect` が1行あれば120歩＝1分で捕まった。
