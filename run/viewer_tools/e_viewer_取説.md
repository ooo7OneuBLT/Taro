## このファイルは何をするか

太郎（乳児の身体モデル）を1枚のGUIで見るための統一Viewer。tkinterの編集パネル（おもちゃ・姿勢・
反射・測定器・再生・脳などの区画）と、MuJoCoの3D描画窓を同時に開き、スライダー操作を毎tick物理へ
反映しながら、視線誘導反射やもがき運動、学習済みの脳（.pt）で太郎を動かして観察できる。
入力は環境変数（E_SCENE・E_AGE・E_SPEED等）とGUI操作、出力はMuJoCoの3D窓・tkinterパネルの表示
更新・`E/docs/viewer_saved.json`または`run/scenes/*.json`への保存。

## 触るときの注意

- **`main()`は1つの巨大なクロージャ関数。** ほぼ全ての変数・ヘルパー関数がこの中に閉じ込められて
  おり、行番号だけでなく「どの変数のスコープに属するか」に注意が必要。offset/limitで一部だけ読むと、
  参照している外側変数（`msg`・`m`・`d`・`env`・`joints`等）の定義箇所が別途必要になることが多い。
- **`msg`（tk.Label）は区画組み立てが全部終わった1591行目で初めて生成される。** それより前に定義
  された関数（`limb_tone_apply`等）が`msg.config(...)`を呼ぶのは問題ないが（呼ばれるのは`msg`生成
  後）、`on_limb_tone()`の**呼び出し**を関数定義直後（区画構築中）に置くと
  `NameError: free variable 'msg' referenced before assignment`で起動時に必ず落ちる（1600-1606行目
  のコメントに実測記録あり）。呼び出し位置は必ず`msg`生成後にすること。
- **key_callback（`_key_cb`、2276行目）は別スレッドから呼ばれる可能性がある。** tkinterウィジェットを
  直接触らず、フラグ（`noise_label_dirty`・`_rc_pending_restore`）を立ててメインループ側
  （`win.update()`と同じスレッド）で処理する設計（2277-2285行目のコメント参照）。ここへ新しい処理を
  足すときは同じパターンを踏襲すること。
- **GUIの表示値と実際の物理適用が別経路になるバグが過去に3回発生している**（監査記録
  2026-08-07・2026-08-10）。もがき運動パラメータ・反射+共通駆動パラメータ・四肢筋力は、いずれも
  「起動時に1回だけ読んで別変数にコピーする」のではなく**毎tick `.get()` で直接読む**設計に統一
  されている。新しいスライダーを足すときもこのパターンを踏襲すること。
- **首のバネ（`nk_k`/`nk_c`/`nk_t`、区画3b）と実験者の手（`hands.hold()`）は同じ`jnt_stiffness`を
  奪い合う。** 頭を抑えている間はスライダーを適用しないガードが2473行目にある。
- **四肢の筋緊張（`st_tone_limb`）と反射+共通駆動（`noise_mode=="reflex_common"`）も同じ
  `jnt_stiffness`を奪い合う。** どちらが勝つかは操作順序依存で未定義（3029-3039行目のコメント）。
  両方ONのときはsnapshot文字列（コピー用）に警告が入る。
- **シーンから起動したとき（E_SCENE指定）は、`env.reset()`だけでは姿勢もおもちゃ位置も既定へ戻る。**
  `_restart[0]`初期値がTrueなので起動直後に必ず再構築ロジックを通る（2386-2425行目）。
- **Windowsには本当のexec関数が無い。** 月齢変更でプロセスを作り直すときは`subprocess.Popen`＋
  自プロセス終了を使う（`os.execve`は使わない。2353-2384行目に理由あり）。
- **触覚順応・口元報酬の監視インスタンス（`_ta_*`）はrun/trainer.pyを経由しない。** Viewerの駆動
  ループはtrainer.pyのreward_contributorsを一切呼ばないため、行動そのものはこれらのスライダーで
  変化しない（表示専用。312-329行目のコメント参照）。

## よくある変更の場所

- **新しいスライダー区画（GUI）を追加したいなら**：`Section(colL または colR, "見出し", 既定開閉)`
  で区画を作り（例：1284行目`sec_run`）、その`.body`にtk.Widgetを積む。既存の区画一覧はファイル
  冒頭のdocstring20-25行目に対応。
- **測定器のラベル文言・判定ロジックを変えたいなら**：2762行目からの`tick % 5 == 0`ブロック
  （測定器・首バネ・触覚順応・口元報酬・輻輳・環境状態の各`*_label.config(...)`）。
- **メインループの駆動方式（脳/もがき運動/反射+共通駆動/停止）の分岐を変えたいなら**：2606-2691行目
  の`if freeze: ... elif st_brain.get(): ... elif st_babble.get()...: ... else: env.step(zero)`。
- **シーンの読み込み・保存の形を変えたいなら**：`_current_scene()`（1637行目）・`save_scene()`
  （1675行目）。ただしシーンの実体（`e_scene.build`/`e_scene.save`）は`run/scene_tools/e_scene.py`
  側にあり、このファイルからは触れない。
- **駆動モード（white/colored/colored+synergy/reflex_common）を増減したいなら**：1306行目
  `NOISE_MODES`リストと、`_set_noise_mode()`（2227行目）・`_set_brain_noise_mode()`（2187行目）・
  `_build_reflex_common()`（1855行目、reflex_common固有の組み立て）を合わせて変更する必要がある。
