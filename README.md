# 太郎

物理シミュレーション上の乳児モデルに、**人間の赤ちゃんが生まれつき持つ仕組みだけ**を与えて、
発達の順番どおりに育てる。正解ラベルも報酬設計も使わない。

高校生1人による個人プロジェクト。2026年6月開始。

---

## 発達段階

人間の乳児の発達順に並べた6つの目標。運動と言語は並行して進む。

| | 目標 | 人間での対応 | 状態 |
|---|---|---|---|
| **A** | オウム返し（親の発声を真似る） | 9〜12か月 | ✅ 完了 |
| **B** | 初語（音に意味がつく） | 10〜14か月 | ✅ 核心は達成 → Fへ |
| **C** | 自己の内部モデル（自分の体の予測） | 0〜6か月 | ✅ 完了 |
| **D** | 他者理解（自己モデルを他者に当てはめる） | 9〜12か月〜 | 🔧 保留（運動発達が前提と判明） |
| **E** | 運動発達（自発運動 → 座位 → 目的的運動） | 0〜12か月 | 🔧 進行中（座位・視線制御まで） |
| **F** | 言語発達の続き（語と物 → 産出 → 二語文） | 12〜24か月 | 🔧 **いまここ** |

順番が前後しているのは、**D をやろうとして壁にぶつかり、原因が「運動発達を飛ばしたこと」だと
分かって E を新設した**ため。依存関係の根拠は [doc/発達依存関係マップ.md](doc/発達依存関係マップ.md) に文献つきでまとめてある。

## 方針

* 太郎の中身は**人間の乳児が生まれつき持つ仕組みだけ**
* 人間に無い便利機能（正解ラベルの注入、決め打ちのしきい値）は使わない
* すべての機能に根拠ラベルを付ける：**【人間模倣】** or **【既存AI研究】**
* 学習の工夫は太郎の中ではなく**環境（親の話し方・育て方）**の側に置く
* 壁にぶつかったら「太郎と人間の赤ちゃんの違いは何か」から考える
* **思っていたのと違う結果も削らずに残す** → [人間模倣からの逸脱リスト](doc/人間模倣からの逸脱リスト.md)

最後の1つが実質的にいちばん重い。逸脱リストには、人間模倣から外れた実装・やってみて駄目だった
設計・原因が分からないままの現象が、理由つきで全部載っている。

## なぜ作っているか

* 軽度の認知症を抱える祖母の介護。人に寄り添うことの難しさを感じた
* ゲーム『Detroit: Become Human』
* フィジカルAIの産業動向。日本はハードウェアでは有望だが、大規模言語モデルでは出遅れている

既存の大規模言語モデルは膨大な知識を扱えるが、目の前の相手を深く理解して寄り添うのは別の問題だと考えた。
人間と同じ順番で育てたモデルなら、人間社会になじめるのではないか。

## 動かし方

**必要環境**：Python 3.12、CUDA対応GPU（無くても動くが遅い）

```bash
pip install -r requirements.txt
```

`requirements.txt` の冒頭に注意書きがある。`pip install` だけでは環境は再現できない
（PyTorch は CUDA版が要る、MobileSAM は GitHub から入れる）。

**走らせる**：入口は1つだけ。実験の内容は JSON ファイルに書く。

```bash
python -m run.main F/experiments/<実験ファイル>.json
python -m run.main F/experiments/<実験ファイル>.json --steps 600
```

実験ファイルは4つの欄でできている。

| 欄 | 中身 |
|---|---|
| `scene` | どんな環境か（`run/scenes/` の名前） |
| `taro` | 太郎の設定（本能のON/OFF・月齢・駆動モード） |
| `run` | 動かし方（種類・ステップ数・シード） |
| `plugins` | 外から測る・見る道具（太郎自身は変えない） |

環境を直接組み立てるコードは書かない。ここを通す。

## 中身

```
taro_core/     太郎そのもの。脳・感覚・内臓。世界のことは知らない
  src/brain/     大脳皮質・小脳・海馬・青斑核・基底核・脊髄 ほか
  src/senses/    視覚・聴覚・触覚・固有感覚・前庭
  src/body/      声道・肺・胃・四肢
run/           太郎を世界に置いて動かす。実験の唯一の入口
  main.py        入口
  scenes/        場面（座位・仰向け・おもちゃの配置）
  plugins/       測る道具（太郎を変えない）
  world/         MIMoのラッパ
MIMo/          太郎の「体」。別研究者の成果。.gitignore対象（別途clone）
A/ B/ C/ D/ E/ F/   各目標の実験ファイル・スクリプト
doc/           プロジェクト全体の記録
replayViewer/  走行の内部状態を再生して見るツール
```

ファイルごとの役割は [doc/太郎の構造.md](doc/太郎の構造.md)、
関数の入出力は [doc/部位の入出力一覧.md](doc/部位の入出力一覧.md)。
どちらもコードから自動生成しているので、規模の数字もそちらが持っている。

## 引用・謝辞

太郎の**体**は **MIMo** です。別の研究者の成果であり、作者が引用を要請しているため記載します。

> Mattern, D., Schumacher, P., López, F. M., Raabe, M. C., Ernst, M. R., Aubret, A., & Triesch, J. (2024).
> MIMo: A Multimodal Infant Model for Studying Cognitive Development.
> *IEEE Transactions on Cognitive and Developmental Systems*, 16(4), 1291–1301.

MIMo は MIT ライセンス。本リポジトリには含めていません。

太郎の**目**には **DINOv2**（Meta AI、Apache 2.0）を使っています。
脳の各部品にも、睡眠リプレイ・予測符号化・内発的動機・小脳の順モデル・内受容などの研究を使っています。

**実際に実装に入れた研究の全一覧**は [引用.md](引用.md)。書誌情報は一次情報で裏を取っています。
「太郎が独自に行き着いた仕組みが、既存研究とどう対応していたか」という**対応関係**は
[関連研究.md](関連研究.md) に分けてあります。前者は事実、後者は主張なので混ぜていません。

## 開発体制

高校生1人の個人プロジェクトです。実装・文献調査・分析には
[Claude Code](https://claude.com/claude-code)（Anthropic社のAIコーディングエージェント）を
ペアプログラマーとして使っています。

研究の方向性・設計判断・「何を検証するか」の**最終判断は著者が行い**、
Claude Code は実装計画の精査・コード実装・文献の一次調査と翻訳・Gitの管理・結果の集計を担当し、
方針を考えるときの相談相手にもなっています。

開発過程の詳細な記録（研究日誌）は、個人的な情報を含むため非公開です。
