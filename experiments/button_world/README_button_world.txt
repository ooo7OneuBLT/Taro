# ボタンのゲーム（button_world）

上から見る版と横から見る版の、色の違うボタンを探すゲーム。JAX で書いてあり、jit・vmap・lax.scan でまとめて並列に回せる。2026-11-08 に作り、同じ日に直しを1回入れた。学習はまだしていない。

ねらい: 横から見るゲームで覚えた「効く色を試して探す」見つけ方を、上から見るゲームでも使えるか（とその逆）を後で測る。

## 中身

- **部屋:** 9×9 マス。観察は RGB 画像（9P×9P×3、uint8）だけ。P（1マスの画素数）は `Config(P=...)` で変える。
- **行動（共通5つ）:** 何もしない・上・下・左・右
- **上から見る版:**
  - 4方向にいつでも動ける。
  - 外周は壁で、扉は外周の1か所。
- **横から見る版:**
  - 床は3段（行7・5・3）で、立って歩く行は 6・4・2。上の2段は幅がランダムで、端から落ちられる。
  - 段の間ははしごでつながる。上・下は、はしごのマスでだけ効く（上からの版との「使い方の違い」）。
  - 足元が空なら1歩ごとに1マス落ちる。
  - 扉は段の左右の端にあり、横からしか入れない（上から落ちても入れず、扉の上に立つ）。
- **ボタン3個:** 6色から重ならずに選ぶ。効くのは1色で、ゲームごとにランダム。乗ると押された絵に変わる（効く・効かないとも同じ）。
- **ボタンでない物3個:** 上から＝宝石、横から＝花。
  - 色は初期値でボタンと同じ3色を1つずつにする（`deco_colors="match"`）。「効く色の物に乗る」だけでは半分しか当たらず、ボタンかどうかの見分けが要る。
  - `"random"`（6色から独立）と `"random_with_good"`（独立だが1つは効く色）も選べる。
- **扉1つ:** 閉じている間は通れない。
- **1回:** 60歩。開いた扉に入ると成功で、点は 1 − 0.5×(歩数/60)。
- **1ゲーム:** 同じ視点・絵柄・効く色で、配置だけ変えた4回。新しいゲームの始まりは `info["new_game"]` で分かる。
- **絵柄:** 視点ごとに3つ。0・1 が練習用、2 が試し用（上から＝砂と木の柵、横から＝雪と氷）。初期値は練習用だけを使う（`themes=((0,1),(0,1))`）。
- **ボタンの形:** 4特徴（外形・輪・高さ・中の印）で作る。
  - 初期値は、横から（練習側）＝板・輪なし・盛り上がり・線、上から＝円・輪あり・平ら・点。4特徴とも違う組で、つまみ 0% にあたる。
  - **似方つまみ `similarity`（0〜1）:** 練習側のボタンとの画素の差（P=5、押す前、灰色の背景）が (1−similarity)×(0%の時の差) に一番近い組を、上からのボタンに使う。1.0 で練習側と同じ形になる（100%の対照）。
  - 視点・絵柄ごとに直接決めたい時は `shape_override` を使う。
- **info:**
  - 位置: 自分、各物の位置と色、扉
  - ゲーム: 効く色、視点、絵柄、回・ゲームの番号、新しいゲームの合図
  - 回の結果: 扉が開いたか、押されたボタン、最初に踏んだ物（-1 なし／0 効くボタン／1 効かないボタン／2 ボタンでない物）、成功
  - **回ごとに入った回数:** `n_good`・`n_bad`・`n_deco`（効くボタン・効かないボタン・飾りのマスに、別のマスから入った回数）
  - **扉が開いてから入るまでの歩数:** `steps_open_to_enter`（扉はいつも見えている。成功しなければ -1）

## 確かめた結果（直し1回目、2026-11-08）

**テスト:** 14/14 通った。確かめた内容は次のとおり。

- 効く色で扉が開く。効かない色・飾りでは開かない
- 閉じた扉は通れない。開いた扉で成功し、点が式どおり
- 上からは外壁を通れない
- はしごで上り下りでき、はしごの上では落ちない
- 横からは、はしご以外で上・下が効かない（上からの版ではいつも効く）
- 段の端から落ちる
- 扉には上から入れない（閉じていても開いていても）
- 入った回数と、扉が開いてから入るまでの歩数が正しい
- 飾りの色がボタンの色と同じ3色になる（`random_with_good` も確かめた）
- ゲームの中で効く色・視点・絵柄が変わらず、4回ごとに新しいゲームになる。試し用の絵柄が練習に出ない
- P=3/5/7/10 で、48通りの形がすべて見分けられる
- 似方つまみが、画素の差で組を選ぶ
- 始めの配置が正しい（物が重ならず、横からは全部が足場のある歩く行にある）

## これまでに仕様から変えた所

- **細かく描いてから縮める:** 形を1マス32画素以上で描いてから、面積の平均で P に縮める。P のまま描くと、P=5 で48通りのうち30通りしか見分けられなかったため。
- **押された形:** つぶさず、沈んで暗くなるだけにした。中の印が消えないようにするため。
- **横からのボタンの置き方:** 下寄せを弱めた。「盛り上がり」がマスの外に出ないようにするため。
- **自分の出だし:** 横から見る版でも、空中から落ちて始まるのはやめ、足場のあるマスから始める。
- **テストと置き場所:** pytest が無いので素の python でも回る形にした。画像は PC の `out/` と、Taro リポジトリの `experiments/button_world/out/` に置いた。

## 気になった所

1. **似方つまみの刻みが不揃い:** 48通りの組から一番近いものを選ぶので、差から見た似方は 0・23・58・77・100% になる。等しい刻みにしたいなら、特徴に連続の量（大きさ・輪の太さなど）を足す必要がある。
2. **差は灰色の背景で測っている:** 実際の画面では、背景（空と草地）と置き方（横は少し下寄せ）も違う。画面の上での差はもっと大きい。
3. **横から見る版は、扉の開いた割合が低い:** 27.9%（上からは 37.2%）。はしごを使わないと届かない段があるため。ランダムの成功率はそろった。
4. **「最初に踏んだ物: なし」が横からで多い:** 15%（上からは 7%）。はしごや段の端で動けない時間があるため。
5. **扉の上に立てる:** 横から見る版で、上の段の端から落ちると扉の上に立つことがある（入れはしない）。見た目は少し不自然。
6. **P=3:** 宝石・花・ボタンがどれも小さな塊に近い。

## 工夫なしのモデルでの動作テスト（2026-11-08）

**モデル:** PPO＋小さな CNN（3層、32ch）＋GRU(256)。入力は画面と、前の行動（one-hot）・前の報酬（RL² / Wang 2018 の標準の形）。

- 記憶は、新しいゲームの始まりでだけ消す。
- パラメータは約160万。
- コードは `scripts/ppo_vanilla.py`（評価も同じファイル）。見張りつきで回す `scripts/run_watched.sh`。図は `scripts/plot_vanilla.py`。

**速さ（学習込み、P=5、各1.5分）:** どの並列数でも、重いのはモデルの計算。ゲームだけなら毎秒約600万歩。

| 並列数 | 毎秒の歩数 | GPU 全体の最大 |
|---|---|---|
| 256 | 20,056 | 5.5GB |
| 1024 | 20,454 | 5.5GB |
| 2048 | 19,635 | 5.5GB |

- 1回の勾配計算に使う量は、64並列分にそろえた。128並列分にすると、GPU メモリが足りなくなった。
- GPU は確保できる量を全体の65%までに制限した（画面表示などが約1.5〜1.9GB 使うため）。

**本番:** 256並列で18分、2,350万歩（毎秒約2.3万歩）。

- モデルは `out/vanilla_main/params_*.msgpack`（約5分ごとと最後）。この PC だけに置く。
- 曲線は `out/vanilla_main/curve.png`、数字は `metrics.csv`・`summary.json`。

**評価（最後のモデル、学習なし、256並列×1200歩）:**

| | 練習用の絵柄・上から | 練習用・横から | 試し用の絵柄2・上から | 試し用2・横から | でたらめ |
|---|---|---|---|---|---|
| 回数 | 22,102 | 16,127 | 5,241 | 5,425 | 8万以上 |
| 成功率 | 99.98% | 99.3% | 7.0% | 12.7% | 3.1% |
| 1回の平均の点 | 0.885 | 0.839 | 0.056 | 0.102 | 約0.02 |
| 最初に踏んだ物: 効く／効かない／飾り／なし | 27／56／17／0% | 24／48／28／0% | 11／22／32／35% | 17／32／43／8% | 15／31／46／7% |
| 回ごとの成功率（1〜4回目） | 100／100／100／100% | 99／99／99／99% | 7／8／6／7% | 13／13／13／12% | — |

**分かったこと:**

1. **ゲームの中で探し方を覚える必要がない:** 1回目から成功率がほぼ100%で、2回目以降に上がらない。最初に踏む物はボタンが約83%で、そのうち効くボタンは約3分の1（3色の偶然と同じ）。色を覚えず、ボタンを片っ端から押して解いている。効かないボタンを押しても損がないので、このやり方が一番よい。
2. **背景が変わると解けない:** 練習に無い絵柄2では、同じ視点でも成功率が 7〜13% に落ちた。上から見る版では、35%の回で何も踏まない（動けていない）。工夫なしのモデルは、背景ごと丸覚えしているように見える。
3. **ボタンと飾りは見分けている:** 練習用の絵柄で最初に飾りを踏む割合は 17〜28% で、でたらめの 46% より低い。

**気になった所（次の直しの候補）:**

- **効かないボタンに罰を付けないと、「効く色を覚える」の検査にならない。** 例: 効かないボタンを踏むとその回が終わる、扉が閉じたままになる、など。今のままでは、2回目以降の伸びも視点の持ち越しも測れない。
- **絵柄2での失敗は、視点の持ち越し以前の問題。** 同じ視点の背景替えで崩れるので、練習用の絵柄を増やすなどして、背景の違いに強くする必要がありそう。

## 効かないボタンのルールの比べ（手書きのプレイヤー、学習なし、2026-11-09）

**足した設定:**

- `wrong_button`（効かないボタンを踏んだ時）:
  - `"none"`＝何も起きない（初期値）
  - `"reset_to_start"`＝その回の始めの場所に戻される。時計は止まらず、押した見た目は付かない
  - `"end_episode"`＝扉が開く前に外れを押したら、その回は失敗で即終わり
- `n_buttons=6`: 6色すべてを使う。飾りの色は、ボタンの色から重ならずに3つ選ぶ。
- info に `entered_button`（入ったボタンの番号）と `wrong_end` を足した。テストは 18/18 通った。

**プレイヤー**（`scripts/players.py`）: ゲームの本当の地図を読み、最短路で動く。厳しいルールでは、押すつもりのないボタンをよけて通る。

- 総当たりの人: まだ押していないボタンのうち、一番近いものへ
- 覚える人: ゲームの中で当たり・外れの色を覚える
- 答えを知っている人: 最初から当たりへ
- でたらめ

**規模:** 12通りの条件（ルール3×ボタン3・6個×視点2）× 4人。各 1024並列×720歩で、でたらめでも各3,072ゲーム。全部で約5分（303.5秒）。表は `out/players/table.txt`、図は `out/players/score_diff.png`、元の数字は `out/players/results.json`。

**覚える人 − 総当たりの人 の点の差（2〜4回目の平均）:**

| | 何も起きない 3個／6個 | 始めに戻される 3個／6個 | 押したら終わり 3個／6個 |
|---|---|---|---|
| 上から | +0.017／+0.036 | +0.027／+0.061 | **+0.500／+0.295** |
| 横から | +0.021／+0.045 | +0.016／+0.018 | **+0.335／+0.140** |

- 一番差が出るのは「押したら終わり」。ボタン3個・上からで、覚える人の点は1回目0.30 → 3回目以降0.91、総当たりの人はずっと0.31。
- 「始めに戻される」は、戻されても数歩しか損をしないので、差が小さい（「何も起きない」と同じくらい）。

**気になった所:**

1. **横から見る版は、外れを踏まずには届かない配置が多い:** 「答えを知っている人」でも失敗する。
   - 「押したら終わり」で 14%（6個で 41%）の回が外れで終わる。
   - 「戻される」で 37%（6個で 71%）の回が時間切れ。
   - 段が1列の通路なので、効くボタンや扉への道の上に外れのボタンがある。厳しいルールで使うなら、配置に「外れを踏まずに届く道がある」という条件を足す必要がある。
2. **上から見る版でも、「戻される」では答えを知っていても 4%（6個で 10%）が時間切れになる:** 扉の前のマスにボタンがある配置などと見られるが、確かめていない。
3. **手書きのプレイヤーの不具合を2つ直した:**
   - ルールが「何も起きない」の時もボタンをよけて遠回りしていた。
   - よけるはずのボタンのマスに入る1歩を、選んでしまうことがあった。
   - どちらも「答えを知っている人」が「総当たりの人」より点が低い、という結果の矛盾から見つけた。
